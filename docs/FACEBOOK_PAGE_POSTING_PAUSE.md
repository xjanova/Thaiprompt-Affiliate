### สิ่งที่ไม่ถูกแตะ

- เพจหลัก "แม่หมอจันทรา" (`107173337600346`): `auto_post_enabled = 1`, โพสต์ตั้งเวลาค้าง 30 โพสต์ตามปกติ
- บอทแชทและการตอบคอมเมนต์ของเพจเลย: `is_active = 1`, `comment_reply_enabled` ยังเป็นค่าตามกลาง
- เพจอื่นทั้งหมด, scheduler, queue worker — ไม่ได้ปิดหรือรีสตาร์ต
- โพสต์ 99 รายการที่ขึ้นหน้าเพจไปแล้วและประวัติในสมุด

### สิ่งที่ยืนยันไม่ได้

- คิวนอกระบบนี้: โพสต์ที่ตั้งเวลาด้วยมือใน Meta Business Suite หลังเวลาที่ตรวจ, แอปอื่น, เครื่องมืออัตโนมัติภายนอก
- โค้ดด่านกลาง (ไฟล์ในเอกสารนี้) **ยังไม่ได้ deploy** — ตอนนี้ production หยุดด้วยสวิตช์และการยกเลิกคิวเท่านั้น
  ถ้ามีคนเปิดสวิตช์รีโพสของเพจนี้ในหลังบ้านก่อน deploy ระบบจะกลับมาโพสต์

## เครื่องมือ: `fortune:facebook-posting-pause`

ไม่ต้อง migration — ธงเก็บใน `fortune_pages.settings_override`
(`FortuneTellingSetting::applyPageOverrides()` ข้ามคีย์ที่ไม่ใช่คอลัมน์จริง จึงไม่กระทบบอทแชท)

```sh
# ดูชื่อ/ไอดีในระบบ เทียบกับที่ Facebook ตอบจริง ของทุกเพจ (อ่านอย่างเดียว)
php artisan fortune:facebook-posting-pause

# ดูเพจเดียว + รายการโพสต์ตั้งเวลาที่ค้าง (อ่านอย่างเดียว)
php artisan fortune:facebook-posting-pause --page-id=PAGE_ID

# หยุดจริง — ยืนยันไอดีและชื่อกับ Facebook ก่อนทุกครั้ง
php artisan fortune:facebook-posting-pause --page-id=PAGE_ID --expected-name="ชื่อเพจบน Facebook" --apply

# ปลดการหยุด — ไม่เปิดสวิตช์โพสต์ให้
php artisan fortune:facebook-posting-pause --page-id=PAGE_ID --expected-name="ชื่อเพจบน Facebook" --resume
```

### `--apply` ทำอะไร

1. ยืนยันกับ Facebook ว่า token ของแถวนี้เป็นของเพจไอดีนี้ และชื่อตรงตัวอักษร — ไม่ตรง = ไม่แก้อะไร
2. ปฏิเสธเพจหลัก (`is_default`) เสมอ
3. ตั้งธง `facebook_posting_paused`, ปิด `auto_post_enabled` และ `repost_enabled`, จำค่าเดิมไว้ใน `facebook_posting_pause_snapshot` (รันซ้ำไม่เขียนทับค่าที่จำไว้)
4. ไล่ `/scheduled_posts` ทุกหน้า แล้วยกเลิกทีละโพสต์ โดยต้องพิสูจน์ได้ก่อนว่าเป็นของเพจนี้ ยังไม่ขึ้น และยังไม่ถึงเวลา — เก็บสำเนาก่อนลบ
5. นับคิวบน Facebook ซ้ำ ถ้าว่างจริงจึงปิดแถว "ตั้งเวลาแล้ว" ที่ยังไม่ถึงเวลาในสมุดรีโพส
   (Facebook ไม่คืน `post_id` ตอนตั้งเวลารูป แถวพวกนี้จึงจับคู่กับรายการในข้อ 4 ไม่ได้)
6. ตรวจแถวที่เลยเวลาแล้วกับ Facebook ว่าขึ้นจริงไหม (cron รีโพสไม่วิ่งให้เพจที่ปิดสวิตช์แล้ว)

คำสั่งจบด้วยรหัสล้มเหลวเมื่อยังมีอะไรค้าง: Facebook ตอบผิดพลาด, ไล่หน้าไม่จบ, ยกเลิกไม่ได้,
หรือยังมีแถว "กำลังส่ง/ตั้งเวลา" ที่ไม่รู้ผล — การหยุดที่บันทึกไปแล้วยังมีผลอยู่ ให้รันซ้ำภายหลัง

คำสั่งนี้ไม่มีทางไหนที่ "โพสต์" — มีแต่อ่าน (GET) กับยกเลิก (DELETE)

### ด่านกลาง `App\Support\FacebookPagePostingGuard`

ลงทะเบียนเป็น middleware ของ Http client ใน `AppServiceProvider` ทุก POST ไปยัง
`/{PageID}/feed`, `/photos`, `/videos`, `/video_reels`, `/photo_stories`, `/video_stories`
จะถูกเช็คธงจากฐานข้อมูล (ตัวเขียน) ก่อนออกจากเครื่อง รวมรอบ retry และ worker ที่ถือค่าเก่า

ครอบ: รีโพสสาขา, แคมเปญคอนเทนต์, mystic, ดวงรายวัน, horoscope campaign, chatbot auto-content
จุดเริ่มสร้างคอนเทนต์ (`generateAndPublish`, `FortuneRepostService::run`) เช็คซ้ำตั้งแต่ต้นทาง
เพื่อไม่ให้ `--force` ลบคอนเทนต์เดิมของเพจที่ถูกหยุด

งานในคิวไม่ถูกลบ — ถูกด่านกันไว้ตอนจะส่ง ข้อความใน log ลงท้ายด้วย `(Facebook publishing paused)`

หลังบ้าน "🔁 รีโพสลงเพจสาขา": กดเปิดสวิตช์ของเพจที่ถูกหยุดจะถูกปฏิเสธพร้อมบอกวิธีปลด

### ข้อจำกัดของด่านกลาง

- รู้จักเฉพาะปลายทางที่ระบุไอดีเพจเป็นตัวเลข — โค้ดใหม่ที่โพสต์ผ่าน `/me/...`, batch
  หรือ HTTP client ที่ไม่ใช่ของ Laravel ต้องเรียก `assertAllowed()` เอง
- คำขอที่กำลังส่งอยู่ ณ วินาทีที่สั่งหยุดอาจไปถึง Facebook — รัน `--apply` ซ้ำหลังจากนั้น
- อ่านฐานข้อมูลไม่ได้ = โพสต์ไม่ออก (ตั้งใจให้ปิดไว้ก่อนเมื่อไม่แน่ใจ)
- แก้ JSON `settings_override` ของสาขาในหลังบ้านแล้วลบคีย์ `facebook_posting_paused` = ปลดล็อกเหมือนกัน
- ติ๊ก "โพสอัตโนมัติ" ของเพจที่ถูกหยุดในฟอร์มสาขายังทำได้ แต่ทุกรอบจะถูกด่านกันและขึ้น error ใน log

## เปิดโพสต์กลับ

เป็นคำสั่งของเจ้าของเท่านั้น — ไม่มีอะไรเปิดกลับเอง

1. `--resume` เอาธงออก และย้ายค่าที่จำไว้ไปเป็น `facebook_posting_last_pause` (มี `resumed_at`)
2. เจ้าของเปิดสวิตช์เองที่หลังบ้าน (ค่าก่อนหยุดของเพจเลย: รีโพส = เปิด, โพสอัตโนมัติ = ปิด)
3. โพสต์ตั้งเวลาที่ยกเลิกไปแล้วไม่ถูกสร้างคืน — ระบบรีโพสจะเติมช่องเวลาใหม่เองในรอบถัดไป
