# โหมด TRANSFER — ดักหน้าแชท FB → ดูดวงฟรีที่เว็บ/LINE

> 2026-07-26 · repo `Thaiprompt-Affiliate` (claude/Main) + `juntraweb` (main)
> 📋 แผน ยังไม่เขียนโค้ด · สโคป: **จุดดักหน้า + ปลายทางฟรี + ทางถอยเปิดบิลบน FB** เท่านั้น

## โหมด

- **`classic` (default)** = ไม่เปลี่ยนอะไรเลย บอทดักแบบเดิมทุกอย่าง
- **`transfer`** = เปลี่ยนกล่องต้อนรับเป็น "ดูดวงฟรี" → กด → เว็บ/LINE → ไพ่ 1 ใบ ทำนายสั้น
  **พยายามนำทางให้ไปให้ได้ แต่ถ้าทำไม่ได้จริงๆ ต้องยอมเปิดบิลให้บน FB** (ถามความสมัครใจก่อน)

### ✅ เจ้าของเคาะแล้ว (2026-07-25 → 26)

| # | เรื่อง | สรุป |
|---|---|---|
| 1 | ฟรีเกิดที่ไหน | **เว็บ/LINE เท่านั้น** · FB ไม่ทำนายฟรีแล้ว |
| 2 | ปลายทางหลัก | **เว็บ** · LINE = ทางเลือก (แต่ LINE คือระบบที่อยากให้ใช้) |
| 3 | ท่อเงิน FB | **ไม่แตะ** — และเป็นทางถอยของ fallback |

## 1. จุดดัก — กำแพงเดียว 3 ทางเข้า (เฉพาะ FB)

`FortuneConversationService::processMessage()` สาขาแยกบรรทัด 2470:

| ประตู | ที่อยู่ | ใคร |
|---|---|---|
| **A** | บรรทัด 2481+ | ลูกค้าใหม่ (ไม่มี reading) |
| **B** | บรรทัด 2405-2464 (`basic_done`/`completed`) | ลูกค้าเก่ากลับมาทัก |
| **C** | postback ใน `FacebookWebhookController` | ปุ่มเก่าค้างในประวัติแชท (`MENU_FORTUNE`/`FORTUNE_BASIC`/`FREE_CARD_START`) |

🚨 ดักแค่ A → ลูกค้าเก่าหลายร้อยคนไม่มีวันเห็นกล่องใหม่ = ดูเหมือนระบบไม่ทำงาน
🚨 ไม่ดัก C → โฟลเดิมรั่วทางประตูหลัง
→ helper เดียว `shouldIntercept()` เรียก 3 จุด · นิยาม "ยุ่งอยู่" ด้วย**ลิสต์สถานะ active** ไม่ใช่ "มีแถว reading ไหม" (`rule_deep_active_statuses_in_guards`)

**ห้ามดัก:** มีบิลค้าง/จ่ายแล้วรอคำทำนาย · เก็บวันเกิด/ถามคำถาม/เปิดไพ่ · `pro_session` · แอดมิน takeover · ข้อความระบบ · **คนที่ยืนยันขอดูบน FB แล้ว (ภายใน 30 วัน)**

## 2. กล่องที่ส่ง — หน้าเดียว

เพราะ "ฟรีใหม่ทุกคน" → ไม่ต้องเช็คสิทธิ์ก่อนส่ง ไม่มีเคส "โฆษณาของที่ให้ไม่ได้"

- 🎁 "ดูดวงฟรี — เปิดไพ่ให้ 1 ใบ" · ปุ่มเว็บ (หลัก) · ปุ่ม LINE (รอง)
- **cooldown 24 ชม.** ส่ง 1 ครั้ง/คน/ช่วง ไม่ใช่ทุกข้อความ (ลูกค้าประจำจะรำคาญ)
- ข้อความถัดไป → AI chat ปกติ + quick reply ท้าย · **ปฏิเสธ = หยุดแนบปุ่ม**
- 🔴 ฉีด directive ให้ AI: "ชวนไปเว็บ/LINE เท่านั้น ห้ามชวนดูในแชทนี้ ห้ามบอกวิธีจ่ายในแชท" ไม่งั้น persona เดิมจะพูดสวนกล่อง

## 3. 🔴 ทางถอย — ยอมเปิดบิลบน FB (ข้อ 9)

### ปัญหาที่ต้องแก้ก่อน: นี่จะเป็น "เกตที่ 4"

ก่อนออกบิลวันนี้มี 3 เกตแล้ว (prod เปิดอยู่จริงทั้งคู่): **กล่องกติกา → ฟังเสียง+พิมพ์รหัส (`enable_consent_audio_code`) → ตอบคำถาม 5 ข้อ (`enable_consent_quiz`)**
คนที่มาถึง fallback = คนที่ทำเว็บ/ไลน์ไม่เป็น (ส่วนใหญ่ผู้สูงอายุ) → เจอ 4 ด่านซ้อน
📌 มีเคสจริงแล้ว: `2026-06-24 LOST — Consent gate trap ดักลูกค้าสูงอายุ → loop เด้งกล่องกติกา` = เสียลูกค้าไปจริง

**→ รวมร่าง ไม่เพิ่มกล่อง:** เอาประโยคยืนยันไปใส่ใน**กล่องกติกาเดิม** + **ผ่อนเกตเสียง+รหัสสำหรับ path นี้** (ตัวที่ดักคนสูงอายุที่สุด)

### กติกา

| หัวข้อ | สเปก |
|---|---|
| trigger | ลูกค้าบอกเอง ("ไม่มีไลน์/กดไม่ได้/ทำไม่เป็น/เข้าไม่ได้/ขอดูที่นี่") · หรือวนขอดูดวงใน FB ครบ N ครั้ง (ตั้งค่าได้ default 2-3) · หรือกดลิงก์แล้วไม่ถึงปลายทางแล้วกลับมาถาม |
| ข้อความ | เสนอทางเลือกสุภาพ + บอก**ความจริง**ว่าเสียอะไร: ไม่มีประวัติย้อนดู · ไม่มีวอลเลต · ไม่มีผังงาน/ค่าแนะนำเพื่อน · ข้อความอาจหายถ้าเพจถูกจำกัด — **ห้ามขู่ลอยๆ** |
| ถาม | **ครั้งเดียว** · ยืนยัน = เข้าโฟลเดิมทันที ห้ามตื๊อซ้ำในบิลนั้น (`rule_listen_dont_pitch_when_declining`) |
| จำสถานะ | ยืนยันแล้ว → จำ 30 วัน ครั้งหน้าไม่ดักซ้ำ (แนบปุ่มเบาๆ ท้ายได้) |
| ฟรี | **ไม่ได้ฟรี** (ฟรีอยู่ปลายทาง) → กลุ่มนี้ซื้อโดยไม่เคยชิม conversion ต่ำกว่าปกติ ยอมรับได้เพราะเป็นกลุ่มเล็ก — **ต้องวัด % ว่าเล็กจริง** |

## 4. ปลายทางฟรี

| | LINE | เว็บจันทรา |
|---|---|---|
| วันนี้ | free card 1 ใบ ทำงานอยู่ **ยาว 1,500-2,000 ตัว** (`FreeCardConversationTrait:357`) | **ไม่มีเลย** — มีแต่หักเครดิต |
| ต้องทำ | ย่อให้สั้น + **auto ทั้งคนเก่า/คนใหม่** (follow event + ทักครั้งแรก) · ไม่ดักอย่างอื่น โฟล 39/99 เดิมครบ | สร้างใหม่ 1 ใบ สั้น + **auto-open ทันทีที่ถึงหน้า** |

### สเปกคำทำนายฟรี
- **ยาว 300-500 ตัว** (ตั้งค่าได้) · ไพ่สุ่ม 1 ใบ · **ไม่ถามวันเกิด ไม่ถามคำถาม**
- **ยึดข้อมูลแม่หมอ ไม่ใช่มโน** → RAG 1,716 rows 22 หมวด เลือกตามหน้าไพ่ (`FortuneKnowledgeService::*LinesForCards()` — pattern card-gated มีอยู่แล้ว เหมาะพอดีเพราะไม่มีคำถามให้จับหมวด)
- **Card-First Mandate** (`buildCardFirstMandate()`) — ทำนายจากหน้าไพ่ ห้ามพูดหลักชีวิตทั่วไป
- **negative guard**: ห้ามอ้าง/มโนวันเดือนปีเกิด ดวงดาว ราศี (ไม่มีข้อมูล — โมเดลเคยมโนมาแล้ว)
- **"ปลายเปิด" = ตอบครบ + ฟันธงชัด** แล้วพ่วง **คำถามต่อยอด 1-2 ข้อ** + "เปิดไพ่ชุดเต็มจะเห็นมากกว่านี้"
  ⚠️ ไม่ใช่ hedge/ตอบครึ่งเดียว — มีเคสลูกค้าด่า "ตอบไม่สุด" มาแล้ว (`2026-06-28 โหมดคุณไสย ตอบไม่สุด`)
  ♻️ ใช้ซ้ำกลไก **NEXTQ** (คำถามแนะนำต่อยอด → ปุ่มกด) ที่ Celtic 99 ใช้อยู่ ย่อมาใช้ได้เลย

### จำนวนที่ตั้งได้
`free_reading_per_person` (1/ช่องทาง) · `free_reading_daily_cap` (กันค่า AI บานปลาย) · `free_reading_length` (300-500) · `free_regrant_at` (วันที่รีเซ็ตสิทธิ์ — "ฟรีใหม่ทุกคน" ทำด้วยค่านี้ค่าเดียว ไม่ต้องแตะข้อมูลลูกค้า)

## 6. สวิตช์

`fortune_bot_mode` = `classic` (default) | `transfer` — ตัวเดียว
ลูกบิดใต้โหมด: `transfer_box_cooldown_hours` · `transfer_fallback_attempts` · `transfer_rollout_percent` + ชุด free_* ข้างบน

1. **resolver คลาสเดียว** ห้ามเช็คโหมดกระจายตามไฟล์
2. **settings cache** — worker daemon ถือ static memo ค้าง → **webhook เห็นโหมดใหม่ / job เห็นโหมดเก่า = สถานะปนกัน** → TTL สั้น 30-60 วิ + `clearSettingsCache()` หัว job + restart worker หลังสลับ (`2026-06-26 ROOT-CAUSE static memo`)
3. สลับกลับ `classic` = ปลอดภัยทันที ไม่ต้องล้างข้อมูล

## 7. ลำดับทำ

**Phase 0** (ครึ่งวัน ไม่มีโค้ด) เปิด `enable_web_fortune_button` + restart worker + **กดลิงก์จาก FB DM ในมือถือจริง** — Messenger เปิดใน in-app webview ไม่ใช่ Chrome · chain `Auth::login`(cookie) → Passport OAuth → juntraweb **ยังไม่เคยพิสูจน์** ถ้าพังตรงนี้ แผนพังทั้งเส้น
**1)** ฟรีสั้นบนเว็บ + auto-open (juntraweb) → **2)** ฟรีสั้นบน LINE + auto ทั้งเก่าใหม่ → **3)** โหมด + กล่องดัก 3 ประตู + ชุดข้อความใหม่ → **4)** ทางถอย FB (รวมกับ consent gate เดิม) → **5)** เปิดทีละ %

⚠️ เปิดโหมดตอนปลายทางยังไม่พร้อม = ลูกค้ากดแล้วเจอหน้าเติมเงิน หลุดทันที

## 8. รายการเสี่ยง

1. ดักทับคนที่จ่ายเงินแล้ว → allowlist เข้ม
2. **fallback กลายเป็นเกตที่ 4 → เสียลูกค้าสูงอายุ** (มีเคสจริงแล้ว) → รวมร่างกับ consent gate + ผ่อนเกตเสียง/รหัส
3. Messenger webview พา SSO ไม่ถึง → วัด clicked vs claimed
4. ปุ่มเก่าในประวัติแชทรั่ว → ดัก postback ด้วย
5. AI พูดสวนกล่อง → directive ในโหมด
6. ฟรีสั้นแล้วลูกค้ารู้สึกด้อยลง → ต้องฟันธงชัด + hook แรง ไม่ใช่ตอบครึ่งเดียว
7. deploy แล้วไม่ restart worker → โหมดไม่มีผล/สถานะปนกัน
8. ค่า AI จากของฟรีที่แจกทุกคน → `free_reading_daily_cap` ต้องมีตั้งแต่วันแรก
