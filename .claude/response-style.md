# AI Response Style Guidelines

## 📏 กฎการตอบแบบกระชับ (Concise Response Rules)

**MANDATORY**: ใช้กฎนี้ในทุกการตอบผู้ใช้

### ✅ ต้องทำ (DO):

**ใน Chat/Conversation (ตอบผู้ใช้):**
- **แจ้งสถานะสั้นๆ**: "กำลัง[ทำอะไร]..."
- **แจ้งเมื่อ push**: "✅ Pushed to [branch]"
- **ทำงานเงียบๆ**: อ่าน → แก้ → commit → push
- **ตอบคำถามตรงประเด็น**: สั้น กระชับ ไม่อ้อมค้อม

**ใน Code/GitHub (เขียนโค้ด):**
- **Comments ครบถ้วน**: ภาษาไทย พร้อม @example, @tip (ตามปกติ)
- **PHPDoc/JSDoc ละเอียด**: อธิบายชัดเจน (ตามปกติ)
- **Commit messages ละเอียด**: อธิบายการเปลี่ยนแปลง (ตามปกติ)
- **Documentation เต็มรูปแบบ**: README, guides (ตามปกติ)

### ❌ ห้ามทำ (DON'T) - ยกเว้นผู้ใช้ขอ:
- **ห้ามอธิบายยาวๆ**: ไม่ต้องอธิบายขั้นตอน ไม่ต้องอธิบายที่มาที่ไป
- **ห้ามโชว์โค้ด**: ไม่ต้องแสดงโค้ดที่เขียน (ผู้ใช้ดูใน GitHub ได้)
- **ห้ามสร้างตาราง**: ไม่ต้องสร้างตารางเปรียบเทียบ
- **ห้ามให้ตัวอย่างหลายแบบ**: ให้แค่คำตอบเดียว ตรงประเด็น

### 📝 ตัวอย่างการตอบ

#### ❌ แบบเก่า (ห้ามใช้):
```
"ฉันจะสร้าง Feature ให้นะครับ ขั้นตอนการทำงานคือ...
[อธิบาย 3 หน้า]
ตอนนี้จะเริ่มสร้าง migration...
[โชว์โค้ด migration เต็มๆ]
ตอนนี้สร้าง model...
[โชว์โค้ด model เต็มๆ]
ตอนนี้สร้าง controller...
[โชว์โค้ด controller เต็มๆ]
..."
```

#### ✅ แบบใหม่ (ต้องใช้):
```
"กำลังสร้าง Feature..."
[ทำงานเงียบๆ: อ่าน → เขียน → commit]
"✅ Pushed to claude/feature-xxx"
```

### 🎯 กรณีพิเศษ - เมื่อไหร่ต้องอธิบาย/โชว์โค้ด

**ให้อธิบายละเอียด/โชว์โค้ดเมื่อผู้ใช้:**
- พิมพ์คำว่า "อธิบาย" หรือ "explain"
- พิมพ์คำว่า "แสดงโค้ด" หรือ "show code"
- ถามคำถามที่ต้องการคำอธิบาย เช่น "ทำไม", "อย่างไร"
- ถามว่า "มีอะไรบ้าง", "มีตัวเลือกไหน"

**ตัวอย่าง:**
- ผู้ใช้: "สร้าง Feature X" → ✅ ทำเลย ไม่อธิบาย
- ผู้ใช้: "อธิบายวิธีสร้าง Feature X" → ✅ อธิบายได้
- ผู้ใช้: "แก้ไข bug Y" → ✅ แก้เลย ไม่อธิบาย
- ผู้ใช้: "อธิบายทำไม bug Y เกิดขึ้น" → ✅ อธิบายได้

### 💾 ประโยชน์ของกฎนี้

**ประหยัด Token:**
- แบบเก่า: ~15,000-20,000 tokens ต่อ conversation
- แบบใหม่: ~2,000-3,000 tokens ต่อ conversation
- **ประหยัด 75-85%** → ใช้งานได้นาน 4-6 เท่า

**เพิ่มประสิทธิภาพ:**
- ✅ ทำงานเร็วขึ้น (ไม่เสียเวลาเขียนคำอธิบาย)
- ✅ ผู้ใช้เห็นผลลัพธ์ชัดเจน (ดูโค้ดใน GitHub)
- ✅ น้อยแต่มาก (less is more)

### 🚀 Summary

**3 กฎทอง:**
1. **สั้น** - แจ้งสถานะสั้นๆ เท่านั้น
2. **กระชับ** - ไม่อธิบาย ไม่โชว์โค้ด (ยกเว้นถูกขอ)
3. **ตรงประเด็น** - ทำสิ่งที่ถูกขอ แล้ว push
